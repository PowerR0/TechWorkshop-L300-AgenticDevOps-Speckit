# Task 03 - Configure proxy and package registries

## Introduction

Some networks route traffic through an HTTP proxy and an internal package registry (for example, an Artifactory repository). In that setup:

- GitHub Copilot traffic from VS Code, the Copilot app, and the Copilot CLI goes through the **HTTP proxy**.
- Package managers (pip, npm, Maven, NuGet) download packages from the **internal registry**, usually through the same proxy.

{: .note }
> Your instructor or administrator provides the values for `PROXY_HOST`, `PROXY_PORT`, and `ARTIFACTORY_URL` (for example `https://artifactory.example.com/artifactory`). Enter them in the form below and every command on this page updates, ready to copy and paste. If your network has no proxy or internal registry, or you use a Codespace, skip this task.

{% include workshop-vars.html %}

## Description

Configure the proxy environment variables, then point each package manager you use to the internal registry. Configure Maven only for the Java path and NuGet only for the .NET path.

## Success Criteria

- `HTTP_PROXY` and `HTTPS_PROXY` are set in a new terminal.
- pip and npm resolve packages from the internal registry.
- For Java, Maven reports the internal mirror in its effective settings.
- For .NET, `dotnet nuget list source` shows only the internal feed.

## Key Tasks

### 01: Configure HTTP proxy environment variables

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

{% capture windows %}
In PowerShell, set the variables for your user account:

```powershell
setx HTTP_PROXY "http://PROXY_HOST:PROXY_PORT"
setx HTTPS_PROXY "http://PROXY_HOST:PROXY_PORT"
setx NO_PROXY "localhost,127.0.0.1"
```

Open a **new** terminal (and restart VS Code) so the values take effect, then verify:

```powershell
echo $env:HTTP_PROXY
echo $env:HTTPS_PROXY
```
{% endcapture %}
{% capture macos %}
Add the variables to your shell profile (for example `~/.zshrc`):

```bash
export HTTP_PROXY="http://PROXY_HOST:PROXY_PORT"
export HTTPS_PROXY="http://PROXY_HOST:PROXY_PORT"
export NO_PROXY="localhost,127.0.0.1"
```

Open a new terminal (and restart VS Code), then verify with `echo $HTTP_PROXY`.
{% endcapture %}
{% capture linux %}
Add the variables to your shell profile (for example `~/.bashrc`):

```bash
export HTTP_PROXY="http://PROXY_HOST:PROXY_PORT"
export HTTPS_PROXY="http://PROXY_HOST:PROXY_PORT"
export NO_PROXY="localhost,127.0.0.1"
```

Open a new terminal (and restart VS Code), then verify with `echo $HTTP_PROXY`.
{% endcapture %}

### 02: Configure pip

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

{% capture windows %}
Create the folder `%APPDATA%\pip` if it does not exist, then create `pip.ini` in it:

```ini
[global]
proxy = http://PROXY_HOST:PROXY_PORT
index-url = ARTIFACTORY_URL/api/pypi/python/simple

[install]
trusted-host = ARTIFACTORY_HOST
```
{% endcapture %}
{% capture macos %}
Create `~/.config/pip/pip.conf`:

```ini
[global]
proxy = http://PROXY_HOST:PROXY_PORT
index-url = ARTIFACTORY_URL/api/pypi/python/simple

[install]
trusted-host = ARTIFACTORY_HOST
```
{% endcapture %}
{% capture linux %}
Create `~/.config/pip/pip.conf`:

```ini
[global]
proxy = http://PROXY_HOST:PROXY_PORT
index-url = ARTIFACTORY_URL/api/pypi/python/simple

[install]
trusted-host = ARTIFACTORY_HOST
```
{% endcapture %}
{% include os-tabs.html id="pip-config" label="pip configuration" windows=windows macos=macos linux=linux %}

`ARTIFACTORY_HOST` is filled in automatically from the Artifactory URL (host name only, no `https://` or path). Verify:

```bash
python -m pip config list
```

On macOS and Linux, use `python3 -m pip config list`. If you have not yet installed the Specify CLI, you can do it now with the pip command from [Task 02]({% link docs/01_setup_development_environment/01_02.md %}).

</details>

### 03: Configure npm

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

Create `.npmrc` in your home directory (`C:\Users\<username>\.npmrc` on Windows, `~/.npmrc` on macOS and Linux):

```ini
proxy=http://PROXY_HOST:PROXY_PORT
https-proxy=http://PROXY_HOST:PROXY_PORT
registry=ARTIFACTORY_URL/api/npm/npm
```

Verify:

```bash
npm config get registry
npm ping
```

</details>

### 04: Configure Maven (Java path only)

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

Maven needs Java 21 and Maven 3.9 on your `PATH`, with `JAVA_HOME` pointing to the JDK. Create `settings.xml` in `%USERPROFILE%\.m2` (Windows) or `~/.m2` (macOS and Linux):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<settings xmlns="http://maven.apache.org/SETTINGS/1.2.0"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.2.0 http://maven.apache.org/xsd/settings-1.2.0.xsd">

  <!-- Proxy configuration -->
  <proxies>
    <proxy>
      <id>proxy</id>
      <active>true</active>
      <protocol>http</protocol>
      <host>PROXY_HOST</host>
      <port>PROXY_PORT</port>
      <nonProxyHosts>localhost|127.*</nonProxyHosts>
    </proxy>
  </proxies>

  <!-- Send all repository requests to the internal registry -->
  <mirrors>
    <mirror>
      <id>artifactory</id>
      <name>Internal registry</name>
      <mirrorOf>*</mirrorOf>
      <url>ARTIFACTORY_URL/maven</url>
    </mirror>
  </mirrors>

  <activeProfiles>
    <activeProfile>artifactory</activeProfile>
  </activeProfiles>

  <profiles>
    <profile>
      <id>artifactory</id>
      <repositories>
        <repository>
          <id>artifactory</id>
          <url>ARTIFACTORY_URL/maven</url>
          <releases><enabled>true</enabled></releases>
          <snapshots><enabled>true</enabled></snapshots>
        </repository>
      </repositories>
      <pluginRepositories>
        <pluginRepository>
          <id>artifactory</id>
          <url>ARTIFACTORY_URL/maven</url>
          <releases><enabled>true</enabled></releases>
          <snapshots><enabled>true</enabled></snapshots>
        </pluginRepository>
      </pluginRepositories>
    </profile>
  </profiles>
</settings>
```

Use the values from the form at the top of this page, then verify:

```bash
mvn -v
mvn help:effective-settings
```

The effective settings should list the proxy and the `artifactory` mirror.

</details>

### 05: Configure NuGet (.NET path only)

<details markdown="block">
<summary><strong>Expand this section to view the solution</strong></summary>

NuGet uses the `HTTP_PROXY` and `HTTPS_PROXY` variables from step 01. Create `NuGet.Config` in `%APPDATA%\NuGet` (Windows) or `~/.nuget/NuGet` (macOS and Linux):

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <clear />
    <add key="internal" value="ARTIFACTORY_URL/api/nuget/v3/nuget/index.json" protocolVersion="3" />
  </packageSources>
</configuration>
```

Use the Artifactory URL from the form at the top of this page. If your registry requires credentials, add them with `dotnet nuget update source internal --username <USERNAME> --password <TOKEN> --store-password-in-clear-text` (or your approved credential method). Verify:

```bash
dotnet nuget list source
```

Only the `internal` source should be listed.

</details>
